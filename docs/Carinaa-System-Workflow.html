1 Ingestion pipeline — slow once, then indexed forever

Runs in background threads with a durable progress state machine; SSE at GET /api/documents/{id}/stream mirrors real stage transitions (never a fake timer).

Uploadroutes_documents.py

Validates size/type against the real capability report; files stored per-workspace.

Parseingestion/parsers/

8 formats (PDF, DOCX, PPTX, XLSX, MD, CSV, JSON, TXT), each returning blocks with provenance.

Clean & Chunkchunker.py

Blocks normalised; sliding window with metadata (section / page range / sheet / unit).

Embedembeddings.py

fastembed ONNX, local, no network, no key — the same vector for chunk and question.

Indexvectorstore.py + SQLite

Chroma holds vectors; SQLite rows are the source of truth (content, offsets, status).

2 Question pipeline — dense, lexical, fused

The Search block below is new: one retrieval_mode setting (per request) selects dense, bm25, or hybrid (RRF). The default remains dense, so every prior answer is byte-for-byte reproducible; the Retrieval Lab is what makes the difference visible.

Understandpipeline._prepare

Follow-up rewrite (standalone question), unit expansion, page/section detection → hard filters. Ambiguity asks, never guesses.

Searchretriever.retrieve

dense: cosine over Chroma. bm25: Okapi BM25 over the identical SQLite scope. hybrid: both, then RRF.

Fuse / Rankhybrid.py

RRF uses position only — Σ weight/(k+rank) — never adding cosine to BM25. Optional cross-encoder re-rank on top.

Contextcontext.py

Token-budgeted assembly; two views of one evidence set (model prompt vs full provenance).

Generatellm/adapter

Online: Groq → Gemini fallback, model chains. Offline: local GGUF only, never online. Every byte of both is streamed.

Verifygrounding + citations

Marker normalisation → citation resolution → four grounding checks → verdict. No evidence ⇒ refusal.

3 Live streaming protocol — POST /api/chat/ask/stream

Server-Sent Events over an authenticated fetch (no token in URLs). Every event below is a fact that happened: stages arrive when the backend records them, tokens arrive as the provider sends them, and the answer is only committed at done. The UI cannot fake any of it.

browser
asks → optimistic user row rendered, AbortController armed (Stop works)
backend
event: ready — conversation + user-message ids, trace id. The optimistic row adopts its real id.
pipeline
event: stage ×N — query_analysis, query_embedding (skipped in bm25), vector_search / bm25_search, rrf_fusion, candidate_retrieval, reranking?, context_building — each carrying real duration + data, fired the moment the TraceRecorder adds it
provider
event: token ×N — real deltas in order (Groq SSE · Gemini SSE · llama.cpp). The draft renders live; Gemini thought-parts excluded; provider committed at first byte (never half-Groq half-Gemini)
pipeline
event: stage — llm_generation (with finish_reason), citation_resolution, grounding
backend
event: done — the canonical AskResponse: assistant row persisted once, trace rows persisted, QueryLog analytics row, full citations + grounding. Draft discarded in favour of this.
any failure
event: error — code + message + trace-up-to-the-failure. Partial text is NEVER persisted; the UI rolls back and the Learning panel shows exactly where it died. Empty/truncated streams fail honestly (providers raise on zero fragments; length-truncation is recorded).
  • Synchronised by construction. The stage dots on the pipeline visual light from the same event queue, so “watch Carinaa think” is observation, not theatre.
  • Buffered twin kept. POST /api/chat/ask shares _prepare_ask / _persist_assistant_turn with the stream, so both endpoints run identical retrieval, scope, persistence, response shape.

4 Evidence trail — from a click on [1] to the exact passage

Per-message trace (Learning Mode)

Every assistant message owns its trace (trace_id on the row, events keyed by message_id). The Steps Behind This Answer tells the story first (Understand → Search → Find → Prepare → Generate → Verify, each one sentence, hybrid stages appear when they ran), then ▸ technical RAG details reveals the raw event stream. The six beginner steps are derived from the message's own top_sources / scope_note / hybrid data — never one global trace reused.

Invariant a failed run's trace is attached to the question row and the panel states the failure — a completed pipeline is never shown next to no answer.

Citation → exact chunk

Citations carry document_id + chunk_id. Clicking [1] opens /app/knowledge/<doc>?chunk=<id>: the viewer asks the backend for that chunk's ordinal, pages to the right page, scrolls it to centre and pulses it (.chunk-focus) with a persistent tint + “this passage” badge. The reader sees the exact sentences the answer was built from.

Export GET /api/messages/{id}/export?format=md|html builds the Evidence Pack purely from stored rows — question, answer, verdict, citations, evidence, trace table, provider — and deep-links each citation back here.

7 Boundaries, and the honesty rules this diagram is drawn under

  • Workspace isolation — every table (SQLite and Chroma alike) is keyed by workspace_id; cross-workspace vector ids are rejected at store level; all routes resolve the owner first.
  • Prompt injection — retrieved text is framed as untrusted data; the prompt carries no secrets; the security bench proves probes are refused (evaluation/security.py).
  • Providers disclosed — which model answered and why a fallback was used is on the message, the trace and the badge.
  • No fakes — no simulated streaming, no timer-driven stage lights, no invented scores/percentages. An empty stream fails; a truncated stream is marked truncated.
  • Scale honesty — reciprocal-rank scores never render as cosine similarities; every score field declares its scale.
  • Tests as contract — 270 fast pytest tests + Playwright browser checks cover the stream framing/persistence, RRF/BM25 maths, export auth + isolation, and the stage-explanations drift guard.
